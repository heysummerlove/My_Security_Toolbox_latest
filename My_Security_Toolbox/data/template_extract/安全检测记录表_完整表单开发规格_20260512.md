# 安全检测记录表完整表单开发规格

## 1. 适用范围

本规格基于以下三份模板整理，可直接用于前后端开发、接口联调和数据库建模：

- `03_detection_record.docx`：安全检测记录表模板
- `08_basic_test_record.xlsx`：附表2 基本信息测试项记录表
- `09_issue_statistics.xlsx`：附表3 设备检测问题统计表

目标输出包括：

- 前端表单字段清单
- 前端表单 JSON 结构
- 后端数据库表结构
- 后端接口字段定义

---

## 2. 设计原则

### 2.1 建模方式

按四层结构建模：

1. 检测记录主表 `record_main`
2. 检测项明细表 `record_item`
3. 问题统计表 `record_issue`
4. 附件表 `record_attachment`

### 2.2 模板对齐原则

- `03_detection_record.docx` 决定逐检测项结构
- `08_basic_test_record.xlsx` 决定设备基础字段、检测项选中结构
- `09_issue_statistics.xlsx` 决定问题闭环字段

### 2.3 文件上传支持

支持以下文件类型：

- 图片：`jpg,jpeg,png`
- 文档：`pdf,doc,docx`
- 表格：`xls,xlsx,csv`
- 原始数据：`bin,fw,pcap`
- 视频：`mp4`

建议后端统一 MIME 白名单：

- `image/jpeg`
- `image/png`
- `application/pdf`
- `application/msword`
- `application/vnd.openxmlformats-officedocument.wordprocessingml.document`
- `application/vnd.ms-excel`
- `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`
- `text/csv`
- `application/octet-stream`
- `video/mp4`

## 4. 前端表单字段清单

字段格式说明：

- `fieldName`：英文名
- `label`：中文名
- `component`：组件类型
- `required`：是否必填
- `placeholder`：输入提示

## 5. 检测项明细统一字段模型

每个检测项统一使用以下字段：

| 英文名 | 中文名 | 组件类型 | 必填 | 输入提示 | 选项 | 上传限制 |

| item_code | 检测项编码 | hidden | 是 | 系统自动生成 | - | - |

| module_name | 模块名称 | hidden | 是 | 系统自动生成 | - | - |
| item_name | 检测项名称 | hidden | 是 | 系统自动生成 | - | - |
| item_description | 检测项描述 | textarea | 是 | 系统自动带出，可允许查看不可编辑 | - | - |
| inspection_mode | 检测方式 | input | 是 | 系统自动带出，可允许查看不可编辑 | - | - |
| inspection_method | 检测方法 | textarea | 是 | 系统自动带出，可允许查看不可编辑 | - | - |
| execution_status | 开展状态 | select | 是 | 请选择开展状态 | 已开展,未开展,不涉及,待补充 | - |
| process_text | 检测过程 | textarea | 是 | 按步骤记录现场操作、工具使用、时间、人员 | - | - |
| result_status | 检测结果 | select | 是 | 请选择检测结果 | 合格,不合格,异常,不涉及,未开展,待补充,无异常,发现问题,可利用,不可利用,成功,失败,匹配,不匹配 | - |

## 12. 推荐校验规则

### 12.1 主表校验

- `report_no` 必填且唯一
- `project_name` 必填
- `sample_name` 必填
- `device_name` 必填
- `test_date` 必填
- `detection_conclusion` 必填
- `record_summary` 必填

### 12.2 检测项校验

- 每个启用的检测项必须有一条明细
- `execution_status=done` 时：
  - `process_text` 必填
  - `result_status` 必填
  - `result_summary` 必填
- `execution_status=not_started/not_applicable` 时：
  - `result_summary` 应说明原因

### 12.3 问题闭环校验

- 若任一检测项 `result_status` 为 `issue_found/fail/abnormal/exploitable`，建议至少录入一条 `issue`
- `issue_fixable=no` 时，`issue_unfixable_reason` 必填
- `issue_fixable=yes` 时，`issue_fix_action` 或 `issue_fix_plan` 至少填写一项

## 14. 开发建议

### 14.1 前端建议

- 基础信息使用普通分组表单
- 检测项使用“模块折叠 + 明细卡片/子表格”
- 问题统计使用可增删行子表
- 附件上传支持按检测项绑定
- 检测项描述/检测方式/检测方法建议由后端配置下发，前端只展示和保存

### 14.2 后端建议

- 检测项主数据单独配置表维护
- 检测记录保存采用事务，主表、明细、问题、附件一次提交
- 导出 Word/Excel 时，以 `record_main + record_item + record_issue` 组合映射模板
